===============================================================================
                       MATHTECH - APPLICATION SUMMARY
              A Digital Workbook for Senior High School Mathematics
===============================================================================


WHAT IT IS
-------------------------------------------------------------------------------
MathTech is a web-based digital workbook for Mathematics. Students read
comic-style lessons, answer graded quizzes, and write a reflection for each
topic. Teachers decide when each topic opens and monitor every student's
progress, scores, and reflections.

Two kinds of users:
  STUDENT  - reads lessons, answers practice and graded activities,
             writes and edits a reflection per topic, sees scores,
             explanations, and personal progress
  TEACHER  - opens or schedules each topic, monitors class progress,
             and reads each student's reflection
             (seeded account only; registration always creates a student)


WHAT IT IS BUILT FROM
-------------------------------------------------------------------------------
MERN stack - MongoDB, Express, React, Node.js.

  FRONTEND
    React 18 .............. user interface
    Vite 5 ................ build tool and dev server
    React Router 6 ........ page routing with role-based guards
    Redux Toolkit ......... quiz answers and module data
    React Context ......... login state and selected topic
    Axios ................. API calls (attaches the login token)
    lucide-react .......... icons (no emojis used anywhere)
    Plain CSS ............. no framework; CSS variables drive the theme

  BACKEND
    Node.js 18+ ........... runtime (ES modules)
    Express 4 ............. REST API
    MongoDB + Mongoose 8 .. database and schemas
    JSON Web Token ........ login tokens, 7-day expiry
    bcryptjs .............. password hashing
    dotenv ................ environment configuration
    cors .................. strict allow-list of permitted origins

  HOSTING
    Frontend .............. Vercel
    Backend ............... Render
    Database .............. MongoDB Atlas

DATABASE (6 collections)
-------------------------------------------------------------------------------
  User ........ fullname, username, email, hashed password, role
  Module ...... one TOPIC: lesson content, objectives, competencies,
                examples, references, publish flag, release date,
                week and topic number (for ordering)
  Activity .... question, type, choices, correct answer, explanation
  Submission .. graded answers, score, percentage, attempt number
  Progress .... which sections a student completed, attempts
  Reflection .. one written reflection per student per topic

  Activity types: multiple_choice, fill_blank, true_false

  API groups: /api/auth, /api/users, /api/modules, /api/activities,
              /api/progress, /api/feedback, /api/teacher, /api/reflections


STUDENT FLOW
-------------------------------------------------------------------------------
  Login -> Topics -> choose a topic -> Competencies
        -> Lesson (Discussion, Concepts, Examples, Reflection)
        -> Practice Exercises (unscored)
        -> Independent Activity (graded)
        -> Feedback (score, answers, explanations)
        -> Review -> Progress


KEY FEATURES
-------------------------------------------------------------------------------
  TOPICS ARE LOCKED BY DEFAULT
    A new topic, a fresh deployment, or a server restart never exposes
    content. Every topic stays closed until the teacher opens it or
    schedules a date. Students see the topic and a countdown, but the
    lesson and quiz are blocked by the server, not merely hidden.
    The teacher's chosen date is saved and survives server restarts,
    and can be edited at any time.

  STABLE TOPIC ORDER
    Topics are always listed in curriculum order (Week 1 Topic 1 first),
    based on stored week and topic numbers - never by release date, which
    would reshuffle the list every time a teacher changes a schedule.

  SERVER-SIDE GRADING
    The correct answer is never sent to the browser, so it cannot be seen
    in the developer tools. The server re-checks every answer on submit.

  MATH-AWARE ANSWER CHECKING
    "P1,234.50", "1,234.50" and "1234.5" are all accepted as the same
    answer, with a small tolerance for centavo rounding.

  COMIC-STYLE LESSONS
    Lessons are written as numbered panels with character dialogue, and
    are rendered as real comic panels with speech bubbles and character
    portraits. New content becomes comic-style automatically.

  REFLECTION PER TOPIC
    After the lesson, each student writes a reflection in their own
    words. It can be edited any time, and shows when it was written and
    last edited. Students are told plainly that their teacher can read
    it. One student can never read or edit another student's reflection.

  TEACHER MONITORING
    Class averages, per-student scores, attempts, completion status, and
    each student's reflection per topic. Refreshes every 30 seconds.

  SMART STARTUP LOADER
    Waits for fonts, character images, and the server to respond, showing
    real progress rather than a fake timer. It always opens the app even
    if something fails, and warns when a sleeping free-tier server is
    taking time to wake up.


CONTENT
-------------------------------------------------------------------------------
  Four topics, grouped into two weeks. Each topic is a separate module so
  it can be opened on its own date.

    Week 1, Topic 1 ....... Sigma Notation and Series
    Week 1, Topic 2 ....... Percentage Change and Inflation
    Week 2, Topic 3 ....... Profit and Loss
    Week 2, Topic 4 ....... Deductions, Tax and Overtime Pay

  Each topic includes:
    6-panel comic discussion
    about 9 key concepts
    4 worked examples
    4 practice items (unscored)
    10 graded items (10 points total)

  All answer keys were verified by submitting them through the live
  grading engine and confirming a 100% score.


DESIGN
-------------------------------------------------------------------------------
  Comic and manga style on a mathematics theme.

    Background .......... cream graph paper
    Cards ............... white grid paper
    Panels .............. navy chalkboard with teal borders
    Accent colors ....... teal, yellow, red, green
    Headings ............ Fredoka One
    Body text ........... Nunito
    Numbers, equations .. JetBrains Mono
    Borders ............. hard offset shadows, no blur, no rounded corners
    Icons ............... lucide-react only, no emojis
    Logo ................ MathTech lockup, used in the sidebar, the login
                          and register headers, and the startup loader


HOW TO RUN LOCALLY
-------------------------------------------------------------------------------
  Requires Node.js 18 or newer and MongoDB running on localhost:27017.

    cd backend                     cd frontend
    npm install                    npm install
    copy .env.example to .env      copy .env.example to .env
    npm run dev                    npm run dev
    -> http://localhost:5000       -> http://localhost:5173

  On first start the backend automatically creates the teacher account
  and all four topics. All topics begin locked; open them from the
  teacher's Schedule page.


ENVIRONMENT VARIABLES
-------------------------------------------------------------------------------
  BACKEND (backend/.env)
    NODE_ENV ..... use "production" when deployed; this is what hides
                   error stack traces from users
    PORT ......... local only; Render provides its own
    MONGO_URI .... local MongoDB or a MongoDB Atlas connection string
    JWT_SECRET ... long random text; use a different one in production
    CLIENT_URL ... the exact frontend address, with no slash at the end
    TEACHER_PASSWORD  password for the seeded teacher account; required
                      in production, where the seeder refuses to use the
                      built-in development default

  FRONTEND (frontend/.env)
    VITE_API_URL . the backend address ending in /api
                   NOTE: this is built into the files, so after changing
                   it you must redeploy for the change to take effect.


KNOWN GAPS
-------------------------------------------------------------------------------
  - Real-time monitoring uses 30-second polling, not websockets. This is
    adequate for a classroom but will not scale to many teachers at once.
  - Lesson HTML is trusted rather than cleaned before display, though
    only teachers can now write it.
  - No automated tests are written, though the tools are installed.
